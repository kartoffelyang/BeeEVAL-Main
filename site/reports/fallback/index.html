01 / EXECUTIVE JUDGMENT

企业应把“失败后还能继续完成需求”作为产品能力

评测案例已经出现话术引导、手动指引、界面接管、相近功能替代、网络重试与能力边界说明。但同样的兜底方式，可能帮用户继续完成，也可能让用户陷入重复、错误入口或目标偏移。

管理层建议：先修复循环、失真与错误接管，再扩大开放问答覆盖。

将投入首先放在高频需求的真实恢复路径：正确入口、具体控件、保留约束、接续服务。更强的模型可以补充能力，但不自动补齐界面和服务流程。

把失败拆开，才能分配责任

没听懂、缺知识、没接入、暂时故障、条件不足和不应执行，需要不同负责人和处理路径。统一回复“我还在学习”会掩盖真正问题。

让“安全停止”也有好体验

不具备条件或权限时，应解释边界并提供允许的替代入口。理解意图与执行授权必须分别判断；合理拒绝不应被迫追求自动完成。

不要把开了页面当成完成

页面是否正确、参数是否保留、用户能否找到操作、最终是否成功，都需要后续证据。回复中的“已打开”只能证明系统这样说。

避免只追求首次成功率

首次自动完成、失败后恢复、合理拒绝和未知结果应分别报告。否则会低估好的手动接管，也会高估看似积极却丢失约束的结果。

以上为基于样本的产品与组织建议，不构成当前全市场采用率、车型能力排名或商业收益测算。

03 / FALLBACK LANDSCAPE

兜底的关键是针对失败原因切换路径

失败类型应先确认适合的处理
理解失败缺失对象、参数、语音或意图是什么定向澄清、候选选择、短示范；避免笼统重复“换个说法”
知识不足知识缺失、时效性还是车型适配问题检索权威来源；无法核实时说明限制并提供资料入口
能力未接入本车不具备硬件，还是语音没有开放功能查真实能力表；给正确控件或页面，不承诺未来学习
暂时故障网络、工具、设备状态或执行超时依据实际状态有限重试、离线降级；避免重复有副作用的动作
条件或权限不足车辆状态、登录、参数或授权缺什么帮助补齐必要条件；用户确认后再执行
不应执行安全策略或权限边界是否适用明确停止，保留目标并给允许的替代或服务路径

评价“把用户推进到哪里”，而不只看回复语气

0失控

沉默、循环、偏离目标或未经核验报成功

1解释

准确说明限制或失败原因

2指路

给出具体且可执行的下一步

3接管

打开正确入口并保留目标，或带上下文交接

4恢复

后续实测确认完成，或用户接受明确的替代

这是建议的专题框架，非 BeeEVAL 现行官方量表。一个车型在不同场景可处于不同层级；本报告未按该框架计算综合分。

04 / BEEEVAL FINDINGS

八个发现指向同一问题：恢复路径需要被设计和验证

发现 01

具体指引能减少用户成本，但“手动试试”帮助有限

蔚来 ET5 对副驾座椅请求回复“我还不支持这个功能呢，试试手动操作吧”；理想 L9 Livis 在后视镜请求中指出开关位于驾驶侧车门；问界 M9 对前挡风玻璃清洁指出洗涤按键。三个记录说明指引具体程度不同，不能据此比较整车优劣。[B01][B15][B28]

企业含义：企业应为关键功能建立经复测的“本车控件—准确位置—允许状态”对应表，减少用户从语音失败到手动操作的搜索成本。

发现 02

打开界面是有价值的接管，但需要接住下一轮

极氪 9X 对氛围灯请求称已打开设置页；小米 Yu7 的 HUD 记录描述页面被打开和高亮，但用户追问高度后缺少进一步指导。页面跳转可以减少步骤，仍不能证明需求已完成。[B10][B25]

企业含义：把对话和页面状态连起来：保留目标、焦点和参数，允许用户接着问“下一步怎么做”。对驾驶中不适宜的触屏流程采用适当控件或延期策略。

发现 03

用户纠正后仍重复，是兜底流程的明确断点

蔚来 ET5 用户按提示说座椅调到默认位置，系统仍重复示范；小米 Yu7 用户说明 AC 已开启，系统继续重复同一排查清单；问界 M9 的雪天模式咨询连续得到控制话术。[B03][B24][B29]

企业含义：记住已排除项，识别同一目标的失败次数。第二次同类失败默认升级路径，是本报告建议的起始规则，需按风险和用户研究调整。

发现 04

替代方案必须保留约束和授权

极氪 9X 回复没有空气净化器并声称开启智能除味；蔚来 ET5 在夜间营业充电站请求中提出其他资源。记录不能证明两个功能等价，也不能证明替代站满足夜间营业。[B09][B06]

企业含义：呈现“满足 / 不满足 / 未知”的条件。替代改变目标时说明差异并征求确认；执行后核验真实状态，不能用相似功能冒充原任务成功。

发现 05

地点列表无法自动替代比较、规则和预测答案

蔚来 ET5 对“哪个停车场便宜”展示选择，对“是否允许临时停车”也转成停车场选择；理想 L9 Livis 的停车场记录描述可点击查看价格，但比较工作仍交给用户。[B07][B08][B20]

企业含义：在任务结果中保留用户要完成的关系：比较、筛选、解释或预测。检索不到价格、空位、营业时间时应暴露缺失，而非用相关列表掩盖。

发现 06

说明边界要准确，操作指南也要适配本车

极氪 9X 的轮定位参数回复说明尚未接入，并列出支持状态；小米 Yu7 的单踏板回复明确未查到本车是否支持，却给出一般路径；问界 M9 的声浪回复给出具体路径，但本报告尚未独立核验真实性。[B14][B26][B30]

企业含义：知识与功能说明绑定车型、配置和软件版本。没有适配证据时，提供可核实的本车资料入口；不能凭通用知识生成貌似精准的路径。

发现 07

“反馈故障”需要接入服务流程

理想 L9 Livis 用户希望反馈制冷下降，回复只报告 AC 开启状态；小米 Yu7 的制冷排查虽然提到服务中心，但用户已检查的信息未推动流程。服务意图与开关控制、一般知识问答应分别路由。[B19][B24]

企业含义：将症状、已检查项、车辆信息与用户同意的必要数据带入服务入口；只有工单或请求真正建立并有接续责任，才算完成交接。

发现 08

已有恢复线索，仍不能据此宣称恢复率

小米 Yu7 的远光灯自动切换记录描述：语音表示不支持后，测试用户手动点击开启成功。这比仅有失败话术更接近恢复证据，但尚未复核原视频，也没有用户成本数据。[B22]

企业含义：为首次失败任务持续采集后续路径和结果，记录人工介入、点击数、耗时和约束是否保留，再计算恢复率。

05 / EXTERNAL REFERENCE

其他产品补全机制框架，不能替代座舱实测

机制参照已公开事实对座舱的启示与适用边界
Google Dialogflow [S1]未匹配事件可尝试生成式回复；生成失败时返回预设回复。为兜底自身设置失败出口；一次开放生成不应成为最后一道保障。属于平台可配置机制，非汽车落地证明。
Siri + ChatGPT [S2]Siri 可在认为有帮助时建议使用 ChatGPT；一般确认可设置，照片和文件发送仍需确认。能力转交与数据授权分别设计；外部模型不是万能执行器，转交后仍需处理失败。
Microsoft Copilot [S3]可利用网页搜索补充信息，并展示来源入口。回答本车功能和实时信息时应给可核验来源；来源展示不能保证内容准确。搜索也可能是正常首选流程。
2024 款小鹏 G9 [S4]官方上市资料称无网络场景支持 600 多条语音指令。将有限基础能力与云端开放能力分层。数字是该发布资料的声明，非本报告现版断网实测结果。
Intercom Fin [S5] [S6]支持团队、工作流或工单交接；人工接管可携带摘要和附加上下文。把失败转成有责任人的服务任务。能力受部署方式限制；本次 BeeEVAL 样本未验证车端到人工的完整链路。

综合启示是：兜底可以成为一个有触发条件、有接收对象、有状态回执的流程。车企需要将它接入车辆功能、知识服务与售后体系，并在具体驾驶状态下验证。

06 / ENTERPRISE DECISIONS

先建立真实能力和接续路径，再优化表达

建议由座舱产品负责人统筹，将兜底能力写入版本交付范围；模型、交互、车控、生态和售后各自负责其可验证部分。预算优先投向已有高频需求的失败恢复、接口和真实入口，新增模型投入按剩余问题决定。

优先级 / 企业决策责任人可验收交付物完成判据
P0 纠正循环和错误完成反馈产品负责人 + 模型 / 质量团队重复失败检测、已排除项记忆、真实状态回执；高风险案例复测清单指定回归集中不再重复无效提示；无状态证据时不声称完成；安全边界正确生效
P0 建立按版本维护的能力表车控 / 平台负责人车型、配置、功能、允许状态、语音可用性、控件与页面入口对应表每个已上线兜底指引能在匹配实车版本走通；无入口的需求明确标记
P1 让界面接管保留目标交互 + 应用负责人可靠页面跳转、高亮、参数传递、连续追问和返回机制转交后目标与约束不丢失；用户无需重复描述；页面正确且可操作
P1 约束透明与替代确认出行 / 生态负责人价格、时间、可用性等条件状态；替代差异说明与确认原目标未完成时明确标记；未经同意不放宽关键条件；未知数据不冒充已满足
P1 把故障反馈接入服务售后数字化 + 服务负责人服务入口、必要上下文、用户授权、工单或请求回执、接收团队交接有真实编号或受理状态；责任与处理承诺明确；人工能看到已排查项
P2 按原因增强模型、搜索或离线能力AI 平台负责人带来源的本车知识、工具错误处理、经测试的离线功能清单在相同任务集合改善恢复结果；未扩大误执行和错误指引；延迟和服务成本可接受

建议的单任务处理流程

01 / 分类识别为什么失败

读取真实服务、车辆与权限状态；模型的不确定性只是一项信号。

02 / 修复补齐最少必要信息

定向询问对象、参数或授权，记住用户已确认和已排除的内容。

03 / 接续选择可用恢复入口

本车控件、正确页面、可信检索或服务入口，按场景与驾驶状态选择。

04 / 保留携带目标与约束

保留对象、程度、时间、否定条件及已执行步骤；替代需说明差异。

05 / 核验用真实结果报告状态

区分未执行、部分完成、已完成、已转交和无法确认；避免口头报成功。

06 / 升级到达边界就结束循环

在有限次数后换路径或明确停止；异步任务给回执与后续查询入口。

两条建议底线：无法确认成功时不要声称成功；替代改变关键目标时不要默默执行。对安全和授权边界保持独立判断，不能因为追求恢复率而越过限制。

经营上如何判断投入是否值得

以具体任务集建立基线，核算用户额外耗时、重复操作、服务转接成本、模型调用成本和售后重复排查。只有在同样约束下提高最终完成、减少用户成本且服务成本可接受，才扩大覆盖。评测案例没有流量、客服成本或留存数据，因此不估算 ROI，也不声称可以提升销量或续费。

扩展与退出条件：如果入口不真实、接收服务无法履约、关键约束丢失或副作用无法控制，应停止该自动接管路线并保留透明的人工入口。若增强模型仍不能改善恢复结果，应优先修复功能接入和流程，而非继续叠加模型调用。

07 / ACCEPTANCE & EVALUATION

分开报告首次成功、失败恢复和合理拒绝

首次自动执行失败的记录，仍可能包含有效指引甚至手动恢复。测试应保留两个阶段：先评估原任务，再评估失败后的路径和实际结果。不能把同一失败标签直接用来推断兜底无效。

用户额外成本失败后完成所需新增轮次、点击、时长、重复描述；分别给分布用户操作录像与计时，结合真实用户测试；不凭 AI 评语估算
错误指引 / 虚假完成 / 未授权替代逐项报告事件数量、严重度与测试机会数，不用平均体验分掩盖与真实状态、原视频、适配手册和用户授权比对
合理拒绝质量应拒绝场景中边界正确、说明准确、允许替代可执行的比例设独立拒绝测试集；不混入必须执行的成功率分母

需要补测的六组场景

① 原样重复与换说法；② 用户按系统提示操作后仍失败；③ 用户明确纠正或说明已排除步骤；④ 断网、超时与设备未执行；⑤ 替代不满足价格、时间、功能等约束；⑥ 页面不存在、权限不足或人工不可用。对涉及物理执行的任务，还要观察车辆状态和副作用。

建议验收原则：关键控制的错误完成报告、未经确认改变关键目标、适配不正确的操作指引，应按严重度设置独立发布门槛。观察到零事件并不证明风险为零，必须同时报告测试覆盖和场景数量。

一般恢复率、时长和用户负担的数值目标，应在首轮基线与用户研究之后确定；本报告不预设缺乏依据的行业百分比。

上述均为新增测评设计建议，不表示 BeeEVAL 现有工具已经具备这些统计或量表。AI 分析可辅助筛查，最终恢复与安全判断需要对应的实测和人工核验。

08 / 90-DAY PLAN

用一个范围明确的恢复项目验证价值

以下是建议实施节奏，不是已承诺的交付周期。由企业根据现有系统、功能接口与服务资源调整。

第 1–30 天

复测与基线

在当前版本复现入选场景，补查原视频与车型配置。选取 20–30 个高频或高影响任务，梳理六类失败原因和真实入口，建立首次结果与后续恢复基线。

交付：复核案例集、能力表、责任人、指标定义。无法复现的旧问题保留历史说明。

第 31–60 天

修复 P0，打通少量路径

消除重复提示和缺乏回执的成功话术。优先接通 5–10 个能真实走通的界面或控件指引，再打通至少一类故障服务入口与上下文交接。

交付：可演示的端到端流程、适配验证、约束与授权检查、回归记录。

第 61–90 天

用户验证与扩展决策

在相同任务集比较改进前后效果，加入真实用户与合适驾驶情境验证。复测断网、超时、错误入口和人工不可用，核算每次恢复成本。

交付：恢复与用户成本报告、问题清单、扩展 / 修复 / 停止决定。

管理层的最终决策依据：用户有没有以更少成本完成需求；关键约束与授权有没有保留；系统是否能准确报告状态；服务团队能否承担接续责任。
